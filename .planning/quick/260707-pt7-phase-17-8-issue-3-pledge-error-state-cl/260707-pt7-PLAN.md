<objective>
Fix Phase 17.8 Issue 3: pledge error state persists even after user corrects input.

**Problem:** When a user enters an invalid pledge amount (below minimum, above wallet balance, above campaign remaining), the validation error renders below the input. If they then edit the input to a valid value, the error persists until form submit or blur/refocus. The input state feels stale and unresponsive.

**Solution:** Add live validation during input change. Clear the error when the current input is valid (non-empty positive number). Revalidate on each keystroke.

**Output:** Updated pledge form that clears/revalidates error live as user types.

Purpose: Improves UX responsiveness for pledge form validation.
</objective>

Update the pledge amount input onChange handler (line 884) to include live validation that clears the pledgeError when the input becomes valid.

Current onChange (line 884):
```
onChange={(e) => setPledgeAmount(e.target.value)}
```

Replace with inline validation:
```
onChange={(e) => {
  const value = e.target.value;
  setPledgeAmount(value);
  // Clear error if input is valid (non-empty, positive number)
  if (value && !isNaN(parseFloat(value)) && parseFloat(value) > 0) {
    setPledgeError(null);
  }
}}
```

This ensures:
- Error clears live as user types a valid amount
- Error reappears on form submit if amount is still invalid
- User sees immediate feedback without needing to blur/refocus
- No changes to validation logic in handlePledge (submit-time checks remain)
